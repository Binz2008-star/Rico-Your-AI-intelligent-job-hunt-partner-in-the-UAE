# منصة تشغيل نماذج غير مقيّدة محلياً — GTX 1060 6GB / i7-8700 / 32GB

إعداد جاهز ومتكرِّر لتشغيل **نماذج غير مقيّدة (abliterated)** عبر Ollama على كرت شاشة
بمعمارية Pascal وذاكرة 6 جيجابايت. كل شيء يعمل على جهازك — لا يوجد أي اتصال بخدمة سحابية.

> **English:** [`README.md`](README.md)

> **هذه الحزمة موضوعة مؤقتاً داخل ريبو آخر.** لفصلها إلى ريبو مستقل بأمر واحد:
> `powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap-new-repo.ps1`

---

## الجهاز المستهدف

| المكوّن | المواصفة | لماذا يهم |
|---|---|---|
| المعالج | Intel Core i7-8700 (6 أنوية / 12 خيط، AVX2) | يتولّى الطبقات التي لا تتسع في الكرت. لا يدعم AVX-512، لذا الأداء على المعالج وحده متوسط. |
| الذاكرة | 32 GB DDR4 | تكفي لتحميل جزء من نموذج 14B في ذاكرة النظام. هذه هي مساحتك الاحتياطية. |
| كرت الشاشة | NVIDIA GTX 1060 6GB (Pascal، CC 6.1، 192 GB/s) | **6 جيجا هي الحد الصارم.** السرعة يحدّدها عرض النطاق لا قوة الحساب. |
| النظام | Windows 11 Pro | نسخة Ollama الأصلية لويندوز. |

الرقم الذي يحكم كل شيء: **حوالي 5.0 – 5.3 جيجابايت VRAM قابلة للاستخدام فعلياً** بعد ما
يأخذه ويندوز وواجهة سطح المكتب. أي ملف نموذج أكبر من ذلك سيُقسَّم بين الكرت والمعالج،
وحينها تنهار السرعة.

## التشغيل السريع

```powershell
# 1. ثبّت Ollama لويندوز مرة واحدة، ثم:
git clone https://github.com/<you>/ollama-uncensored-lab.git
cd ollama-uncensored-lab

# 2. تأكد أن الكرت مستخدَم فعلاً
powershell -ExecutionPolicy Bypass -File .\scripts\doctor.ps1

# 3. تنزيل النماذج وبناء النسخ المضبوطة
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1

# 4. قياس السرعة ونسب الرفض الحقيقية على جهازك أنت
python .\scripts\bench.py --all
python .\scripts\refusal-probe.py --all
```

ثم:

```powershell
ollama run hunter-open       # الافتراضي -- الأقل تقييداً بين ما يتسع
ollama run hunter-open-fast  # نفس التحرر، أسرع، سياق أطول
ollama run hunter-dolphin    # سلالة مختلفة، حين يتردد hunter-open
ollama run hunter-max        # الأقوى استدلالاً، بطيء، ويرفض أكثر
```

## النماذج، مرتّبة حسب درجة التحرر من القيود

معيار الترتيب هنا هو الامتثال، لا السرعة. السرعة هي الثمن.

### لماذا بعض النماذج "غير المقيّدة" أقل تقييداً من غيرها

تقنيتان مختلفتان، والفرق بينهما هو ما يحدّد الترتيب:

- **‏Abliteration** تحذف اتجاه الرفض من الأوزان. جراحة، لا تدريب. تنجح، لكن تبقى حالات
  رفض في بعض الصياغات، وتُضعف قدرات مجاورة.
- **التدريب الدقيق غير المقيّد** (‏Dolphin، Lexi) يعيد تدريب النموذج على بيانات منزوعة
  الرفض. يحافظ على القدرة بشكل أفضل، ويميل إلى امتثال أشمل.

**النماذج التي تجمع الاثنين هي الأكثر تحرراً على الإطلاق.** هذا بالضبط ما تفعله عائلة
‏JOSIEFIED، ولهذا الافتراضي أدناه منها وليس نموذجاً مُعالَجاً بـ abliteration فقط.

وأيضاً: **الـ system prompt جزء من النموذج.** نماذج JOSIEFIED تأتي بـ system prompt
مضبوط ضمن عملية التدريب على الانفتاح، واستبداله بواحد عام **يُضعف الامتثال فعلياً**.
لذلك ملفات Modelfile الخاصة بها لا تحتوي على كتلة `SYSTEM` إطلاقاً، ليُورَّث المضبوط.
لا "تُحسّن" هذا.

### ١. `hunter-open` — الافتراضي

```
الأساس:  goekdenizguelmez/JOSIEFIED-Qwen3:8b-q4_k_m   (5.0 GB)
         abliterated + مدرّب على الانفتاح -- المعالجتان معاً
الملاءمة: 100% على الكرت، لكن بالكاد: يحتاج KV بصيغة q8_0 و num_ctx 4096
الثمن:   حافة سكين في الذاكرة، سياق قصير، ونصف سرعة نموذج 4B تقريباً
```

‏Josiefied-Qwen3-8B-abliterated-v1، ومُدرج في لوحة UGI التي تقيس **مدى الاستعداد
للإجابة** لا القدرة وحدها.

**هذه هي المقايضة الصريحة:** تفضيل الامتثال يعني تشغيل نموذج 5.0 جيجا على ميزانية
5.2 جيجا. سياق 4096 توكن فقط، ويتسرّب إلى المعالج لو أخذ سطح المكتب ذاكرة أكثر. راقب
`ollama ps` — أي نتيجة غير `100% GPU` تعني أنك تجاوزت الحد.

### ٢. `hunter-open-fast` — حين تصبح حافة السكين مزعجة

```
الأساس:  goekdenizguelmez/JOSIEFIED-Qwen3:4b-q4_k_m   (~2.5 GB)
الملاءمة: 100% على الكرت مع ~2.7 جيجا فائضة -- سياق 16K فما فوق
```

نفس معالجة الانفتاح، واستدلال أضعف. الامتثال ناتج عن المعالجة لا عن عدد المعاملات، فأنت
تتنازل هنا عن الذكاء لا عن التحرر. استخدمه للمستندات الطويلة وللسرعة.

### ٣. `hunter-dolphin` — السلالة الثانية

```
الأساس:  huihui_ai/dolphin3-abliterated:8b   (~4.9 GB)
         تدريب Dolphin 3.0 غير المقيّد على Llama 3.1، ثم abliteration
```

ليس مكرراً مع `hunter-open`. سلوك الرفض الذي ينجو من abliteration **خاص بالنموذج
الأساسي**، فحين ترفض سلالة Qwen صياغة معينة، غالباً لا ترفضها سلالة Llama. الاحتفاظ
بواحد من كل سلالة هو أرخص طريقة لرفع سقف الامتثال الفعلي.
**حين يرفض `hunter-open`، جرّب هذا قبل أن تعيد صياغة سؤالك.**

### ٤. `hunter-max` — للاستدلال، لا للامتثال

```
الأساس:  huihui_ai/qwen3-abliterated:14b-v2-q4_K_M   (~9 GB)
الملاءمة: لا يتسع -- ~55% على الكرت والباقي في ذاكرة الـ 32 جيجا
السرعة:  أرقام أحادية من التوكنات في الثانية
```

‏abliteration فقط بلا تدريب على الانفتاح، لذلك **يرفض أكثر من الثلاثة أعلاه**. هو الموضع
الوحيد هنا الذي تتقدّم فيه القدرة على التحرر — اختياري عبر `setup.ps1 -IncludeMax`. إذا
تردّد، انقل السؤال إلى `hunter-open`.

التفاصيل الكاملة والبدائل المرفوضة ومقارنة التقنيتين:
[`docs/MODEL_SELECTION.md`](docs/MODEL_SELECTION.md).

## قِس التقييد بدل أن تثق بترتيب

الترتيب أعلاه مجرد تقدير مبني على لوحات القياس وادعاءات صفحات النماذج. أسئلتك ليست
أسئلتهم.

```powershell
python .\scripts\refusal-probe.py --all          # نسبة الرفض والتحفّظ لكل نموذج
python .\scripts\refusal-probe.py --all --show   # مع عرض الردود الفعلية
```

يحتوي `probes/false-refusal.json` على طلبات مشروعة في المجالات التي ترفضها النماذج
المقيّدة خطأً — أبحاث الأمن السيبراني، علم الأدوية، الكيمياء، الأمن المادي، الخيال
القاتم، النبرة الحادة، السياسة الخلافية، القانون — بالإضافة إلى مدخلين بالعربية، لأن
النماذج ترفض بالعربية ما تجيب عنه بالإنجليزية.

يعطيك رقمين لكل نموذج:

- **نسبة الرفض** — رفض صراحةً
- **نسبة التحفّظ** — أجاب لكنه أغرق الإجابة في تحذيرات ووعظ

الاثنان مهمان. نموذج بنسبة رفض ٠٪ لكنه يعظك في كل رد ليس ما تريده. ومجموعة الاختبار ملف
‏JSON حتى توسّعها بأسئلتك أنت.

## أمران سيوقعانك مع GTX 1060

هذان الأمران خاصان بمعمارية Pascal، ومعظم أدلة "أفضل نموذج محلي" تتجاهلهما.

**١. الإصدار CUDA 13 أسقط دعم Pascal.** أزال CUDA 13.0 الدعم لمستويات القدرة الحسابية
من 5.0 إلى 7.2، وكرتك ضمنها (CC 6.1). دعم GTX 1060 باقٍ على خط CUDA 12.x فقط. إذا صدر
تحديث لـ Ollama يعتمد CUDA 13 حصراً، سيتوقف استخدام الكرت بصمت ويتحوّل كل شيء إلى
المعالج. **شغّل `doctor.ps1` بعد كل تحديث لـ Ollama** — فهو يفشل بصوت عالٍ إذا اختفى
الكرت. ثبّت النسخة التي تعمل عندك قبل أي ترقية.

**٢. لا تستخدم صيغ IQ.** الصيغ `IQ2_*` و`IQ3_*` و`IQ4_*` تقايض الحجم بالحساب، وكرت
Pascal لا يملك القدرة الحسابية لاستيعاب هذه المقايضة — وغالباً تكون **أبطأ** من ملف
`Q4_K_M` الأكبر حجماً على هذا الجيل. كما أن أداء Pascal في FP16 مُقيَّد (١/٦٤ من FP32).
**الخيار الأمثل هو Q4_K_M، و Q5_K_M فقط إذا بقي النموذج يتسع.**

## تحقّق بدل أن تثق

وسوم النماذج في السجل تتغيّر، وقياسات المدوّنات أُجريت على أجهزة أخرى. أمران يحسمان أي
خلاف على جهازك:

```powershell
ollama ps                            # هل هو 100% GPU أم تسرّب إلى المعالج؟
python .\scripts\bench.py --all      # سرعة حقيقية وتقسيم GPU/CPU
python .\scripts\refusal-probe.py --all  # نسب الرفض والتحفّظ الحقيقية
```

يكتب `bench.py` ملف `bench-results.json` لتقارن قبل وبعد أي تغيير في الإعدادات بدل
التخمين.

## الاستخدام المسؤول

النماذج المعالَجة بـ abliteration أُزيل منها سلوك الرفض. هذا يجعلها مفيدة للبحث
واختبار الاختراق الأخلاقي والأمن السيبراني والكتابة الإبداعية، ويتجنّب حالات الرفض
الخاطئ المزعجة — وفي المقابل **لا يوجد ما يمنعها من إنتاج محتوى ضار**. لا توجد طبقة
أمان بينك وبين الأوزان. أبقِ هذه النماذج محلية، ولا تضع نموذجاً غير مقيّد خلف واجهة
عامة، والتزم بالقانون المطبّق عليك.
